Client helpers

Ready-to-use sink helpers. Server apps use API key on POST /api/v1/logs / /batch. Browsers use client token on POST /api/v1/client/logs.

Note: tiny-log-agent ships host/service metrics only. Application logs always go over HTTP with these helpers.

Source files: tinylog.go tinylog.mjs tinylog.js

Contract

  • Levels: debug info warn error fatal
  • Required: app, level, message
  • Optional: source, timestamp (RFC3339), meta
  • Auth: Authorization: Bearer <token>

Fiber usage

usage
tl := tinylog.New(tinylog.Config{
  BaseURL: os.Getenv("TINY_LOG_URL"),
  APIKey:  os.Getenv("TINY_LOG_API_KEY"),
  App:     "my-fiber-api",
  Source:  "fiber",
  OnUnable: func(err error, entries []tinylog.Entry) {
    log.Printf("unable to send log: %v", err)
  },
})

_ = tl.Log(ctx, tinylog.Info, "hello", map[string]any{"path": "/"})

Usage

usage
import { TinyLogClient } from "./tinylog.mjs";

const tl = new TinyLogClient({
  baseUrl: process.env.TINY_LOG_URL,
  apiKey: process.env.TINY_LOG_API_KEY,
  app: "my-node-api",
  onUnable(err) { console.error("unable to send log", err.message); },
});

await tl.log("info", "hello", { path: "/" });
Use TINY_LOG_CLIENT_TOKEN only in the browser — never the server API key.
